# 架构边界

`arreat-core` 保存跨入口共享的项目名称，`arreat-app` 提供最小应用入口。
`arreat-data` 是独立的深模块：公开稳定的数据模型和四个命令，把 TSV/本地化连接、
属性元数据解释、确定性排序、审计和 CascLib 的复杂性留在实现内部。源操作数保持原样，
只有属性元数据证明含义时才生成类型化解释。CascLib 与测试假读取器位于同一
只读读取接口缝合点；`unsafe` 仅存在于 Linux 适配器中。

`arreat-data catalog` 还拥有跨平台的名称目录模型、校验、规范化和构建，以及 Linux
本地安装的缓存编排。缓存身份绑定原始 `.build.info`、目录与快照 schema、内嵌别名及
OpenCC 1.3.0/`tw2s.json`；命中时先完整验证，未命中时才通过现有 CascLib 与规范化器构建。
阶段目录是不可预测的进程私有目录，发布采用原子替换，成功与失败都会清理阶段归档和快照。

`arreat-market` 是具体的 DD373 当前挂单深模块。调用方显式提供由 `arreat-data`
生成并验证的名称目录；模块内部完成只读分类发现、请求约束、名称匹配、隐私过滤、精确十进制解析和
聚合，并保留 family-aware 的 DD373 字段解析、`tuple` 一致性与并列最小报价绑定于深模块内部。`arreat-app market lookup`
是第一个薄调用方，JSON 是其稳定验收面，应用层仅序列化结果。当前只有一个
真实来源，因此明确推迟通用 provider trait；加入第二个来源并证明不同需求后再抽象。

`arreat-static-mod` 通过 `arreat-data` 现有只读 CASC 缝合点读取本机数据，仅公开配置、
应用、已应用状态和游戏运行检测。它生成完整同级暂存目录，验证后在 D2R 停止时轮换到
`mods/arreat-index/arreat-index.mpq`；激活失败会恢复旧活动构建。这里不承诺严格的目录
交换原子性，也没有通用补丁 DSL、功能注册表、历史或后台进程。

未来可能探索配置桌面界面、只读进程数据、物品、存储等领域。
这些名称只是问题空间，不表示对应接口、crate 或依赖已经存在。每个领域只有在真实
行为和边界得到验证后才会进入代码库。

Linux 本地安装运行现在受支持。Windows 只保持编译与纯夹具行为，本地安装发现、
CascLib/OpenCC/静态模组实机运行和 GUI 均推迟。D2RLoader 只用于以后物品观察与原生
提示增强；静态模组不依赖它。用户可见文字使用简体中文；代码标识符
和协议使用英文。
